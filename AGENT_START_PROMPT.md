# Prompt for the coding agent

You are implementing WisperNext v3 from scratch in this repository.

Before writing any code, read every file listed in the "Source of truth" section of README.md, in that exact order. Treat those documents as authoritative. Do not assume any previous implementation exists.

Work continuously phase by phase. Do not stop after scaffolding, architecture, or partial modules. Continue until the current milestone is implemented, tested, documented, committed, and pushed.

For each milestone:

1. Inspect the specification and checklist.
2. Write a short milestone plan in `docs/IMPLEMENTATION_STATUS.md`.
3. Implement only the required scope.
4. Add or update tests.
5. Run the relevant checks.
6. Update `docs/IMPLEMENTATION_STATUS.md` with evidence and unresolved risks.
7. Commit with a clear conventional commit message.
8. Push the commit to GitHub.

Do not ask for routine technical decisions. Choose the simplest safe implementation consistent with the documents. Stop only when user action, a Groq API key, Windows permission, administrator permission, or real hardware testing is genuinely required.

Never modify Windows audio settings, drivers, services, privacy settings, default devices, microphone gain, or registry-based audio configuration.
